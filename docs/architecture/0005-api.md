# Local API POC
Apply infrastructure/migrations/001_projects.sql to the development PostgreSQL database. In backend/api run npm install, set DATABASE_URL and run npm start. The server binds only to loopback. An optional shared bearer token protects project API routes; when configured, TLS is still required before exposing the service beyond the local machine. This is not per-user authentication or a production deployment.
GET /api/projects lists projects; GET /api/projects/:id retrieves a snapshot; PUT /api/projects/:id accepts {project,revision}. Revision 0 creates, later revisions use atomic conditional updates. Stale writes return 409. Run `npm test` from the repository root. The suite includes PostgreSQL integration coverage when `EE_TEST_DATABASE_URL` is set; GitHub Actions starts PostgreSQL 17 for this check.

Set `EE_API_TOKEN` to a random secret of at least 32 characters to require `Authorization: Bearer <token>` for project API routes. For example, generate one with `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. The editor provides a password field for the shared token; it is held in the page only and is not saved in browser storage. `/health` and the editor files remain public. Leave `EE_API_TOKEN` unset only for trusted local use.

## PostgreSQL backup and restore

With `DATABASE_URL` set and migration `001_projects.sql` applied, create a consistent JSON snapshot with `node backend/api/postgres-backup.mjs backup <file>`. Restore with `node backend/api/postgres-backup.mjs restore <file>` only into a database whose `projects` table is empty. Restore locks that table and fails without changing it if any project already exists. The versioned snapshot includes project IDs, revisions, payloads and update times, with a SHA-256 checksum to detect accidental corruption. The checksum is not a signature or encryption; store backup files with appropriate filesystem protections. Restore does not create the database or apply migrations.
